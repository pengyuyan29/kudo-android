# Agent Note: 按楼层分组的全屏图片相册与返回定位

Status: proposed

## Problem

图片路由只携带一个 URL，无法翻看同帖多图，也不能从当前大图缩回对应图片。列表的图片点击被整张话题卡片接收；旧查看器的固定按钮和无边界缩放不符合全屏阅读需求。

## Proposal

以主帖或单条评论为相册边界，保留每次图片出现的稳定标识，重复 URL 不合并。列表点击图片时立即显示预览，并按需读取该主帖的全部图片；读取失败保留已打开图片并允许重试。列表返回时将当前图同步至同一预览位，正文返回时将该楼层内的当前图片带入可视范围。

查看器放在同一窗口的根覆盖层，保留原页面组合、滚动位置和图片定位信息；不把整组图片编码进导航 URL。覆盖层隔离背景触摸、焦点与可访问语义。关闭前定位当前图片，随后从大图实际边界过渡到目标边界；源位置失效时淡出，不飞向首次点开的错误图片。状态在图片加载、横竖屏与重复开关时保持一致，转场遵循系统动画设置。

相册使用 Compose HorizontalPager 与现有 Coil 加载器。缩放围绕双指中心，拖动受实际图片边界约束；原始比例的横滑交给相册，向下拖动缩小图片并淡化背景。单击、下拉或系统返回关闭，长按显示图片信息与浏览器入口；无常驻顶部按钮。手势取消恢复到原位，缩放和翻页不能误触关闭。

## Alternatives considered

- 给原 image 路由增加 URL 数组：沿用导航最直接；原页面被移出活动组合后，定位尚未可见的第 3 张会更复杂，覆盖层保留源页面更适合双向动画。
- 只对首次图片应用导航 shared element：Compose 能自动管理过渡；不能独自解决切换页面后的源项定位、列表单预览位同步与拖动关闭，使用明确的相册会话和来源定位协议。
- 为图片引入新的完整浏览库：缩放与分块解码有成熟方案；这次主要边界在来源定位和全屏手势协调，先复用现有 Compose / Coil。若超大长图的清晰度或内存成为已验证问题，再考虑分块解码。

## Acceptance criteria

各入口验证第 1 张放大、滑到第 3 张、缩回第 3 张；评论相册不能混入其他楼层或 emoji。覆盖横滑、双指中心缩放、边界拖动、下拉取消与关闭、单击、系统返回、重复 URL、加载失败和系统关闭动画。真机与酷安对照截图及转场采样，测试夹具不冒充线上内容。

## Risks

列表完整相册首次需要一次只读主帖请求。源内容刷新或消失时不能保证缩回动画，须安全淡出。超大静态图片继续受 Coil 采样约束，不承诺无限原像素缩放；动图生命周期沿用现有边界。

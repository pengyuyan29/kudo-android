# Agent Note: 已登录个人中心与网站消息分组

Status: proposed

## Problem

已登录的个人中心仍使用大标题、独立卡片背景和大尺寸 Material 菜单，缺少社区摘要与常用个人功能。消息只有混合列表，不能按网站分组访问。

## Proposal

功能以 FluxDO e1bd839 的个人中心为参照，独立实现 Kotlin 界面与接口，不复制 GPL Flutter 源码。用户确认本期不包含 AI、LDC/CDK、导出管理；“我的”标题及其右侧设置按钮均移除。保留已完成的访客界面。

分三个单元：沉浸式资料标题和摘要；个人内容与社区入口；网站消息分组。每个可用的小功能独立中文提交，功能完成后集中运行回归。

顶部只使用 profile_background_upload_url，加遮罩覆盖状态栏，空值或加载失败使用 LogoYellow；头像进入个人主页，没有独立“查看个人主页”行。状态栏颜色通过主题单一入口管理，离开页面恢复。摘要来自 /u/{username}/summary.json，默认访问天数、已读帖子、获赞、发帖数，失败不冒充零。账号身份和取消作用域隔离辅助读取。

主快捷入口是话题、收藏、草稿、历史；下方包含私信、聊天、待审核、徽章、等级条件、权限允许的邀请，以及站点导航、界面显示、关于。菜单使用酷安式小图标、紧凑网格和扁平行。Connect 独立限定来源读取真实等级条件，认证或结构变化提供应用内网页恢复，绝不向其他域转发主站 Cookie。

通知按所有通知、回复、赞、私信分组。保留服务器类型和导航信息，完整分页后过滤，不能过滤当前一页就宣称没有更多结果。账号变化取消旧请求和缓存，标记已读仅由明确点击触发。真实账号验收只读，写操作使用离线夹具。

## Alternatives considered

- 整个个人中心使用网站 WebView：能最快覆盖全部功能，但用户明确要求酷安式原生密度，核心资料和个人内容使用原生展示，网页仅承载需要网站认证或独立复杂流程的入口。
- 按通知类型向普通分页接口传 filter_by_types：看似能让服务器分页，但上游控制器仅在 recent 分支使用类型筛选；recent 会更改 last_seen 且不是完整分页。使用完整分页和明确类型分组。
- 用当前一页做分组：实现简单、切换快，但回复或赞可能在后续页，必须保留继续加载能力。

## Acceptance criteria

- 标题图延伸到状态栏，失败回退黄色，切页状态栏图标恢复；无“我的”标题、顶部设置或独立主页按钮。
- 四项真实统计具有加载、错误和重试状态，账号切换不混用。
- 入口有有效目的页，草稿不丢失，私信与聊天不混为同一种消息。
- 四组通知可以切换和分页，已读状态以服务器成功为准，旧账号响应不能写回。
- JVM、必要 Compose 真机用例、Lint、verify-notes 通过；同签名覆盖安装保留登录。

## Risks

Connect 是 HTML 契约，页面或认证变化需要恢复入口；聊天和邀请等权限由服务器决定。真实验收不能覆盖发帖、发私信、邀请等产生社区数据的操作，这些使用夹具验证。
